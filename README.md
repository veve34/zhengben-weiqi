# 正本围棋 · 会员系统后端 MVP

给工程师的交接说明。前端画面沿用既有设计，本次补上的是真实可运行的会员注册/登录/内容管理后端。

> ⚠️ **升级注意（2026-08-01）**：`users` 资料表结构做了破坏性变更——注册栏位由「真实姓名 / 手机号 / 身份证号」改为「用户名 / 邮箱 / 身份证照片」，栏位是整组抽换的，`CREATE TABLE IF NOT EXISTS` 不会替既有资料库补上。
>
> 若你手上已有旧版的 `data/app.db`，直接拉新版程式码会因为找不到栏位而报错。目前尚未正式上线、资料库里只有示范资料，处理方式是**删掉重建**：
>
> ```bash
> rm -f data/app.db data/app.db-wal data/app.db-shm
> npm start        # 重新建表
> npm run seed:demo # 重新灌入示范资料
> ```
>
> 若日后已有真实会员资料才需要改结构，请改写迁移脚本，不要直接删库。

## 快速开始

```bash
npm install
cp .env.example .env
# 编辑 .env，填入 JWT_SECRET、ADMIN_PASSWORD
npm start
```

打开 `http://localhost:3000` 即为会员网站，`http://localhost:3000/admin.html` 为围棋知识内容管理后台（用 `.env` 里的 `ADMIN_PASSWORD` 登录）。

## 目录结构

- `server.js` — 入口，挂载路由、提供 `public/` 静态文件
- `db.js` — SQLite 数据库与建表（首次启动自动建立 `data/app.db`）
- `routes/auth.js` — 注册 / 登录 / 登出
- `routes/member.js` — 会员中心资料查询
- `routes/articles.js` — 围棋知识文章（公开查询 + 后台管理）
- `routes/admin.js` — 管理员登录
- `routes/adminMembers.js` — 会员审核（查询/通过/驳回）
- `routes/listings.js` — 二手棋具信息发布（发布/查询/留言/标记售出/下架）
- `routes/adminListings.js` — 二手棋具管理（后台强制下架）
- `routes/captcha.js`、`services/captcha.js` — 图形验证码（本地产生 SVG，不依赖任何外部服务）
- `middleware/upload.js` — 二手信息图片上传（multer，存于 `public/uploads/listings/`，可公开访问）
- `middleware/uploadIdCard.js` — 身份证照片上传（存于 `data/id-cards/`，**不对外公开**，详见下方说明）
- `public/*.html` — 会员网站前台，多页式结构（见下）
- `public/admin.html` — 内容管理后台
- `public/css/style.css`、`public/js/common.js` — 前台各页共用的样式与脚本（会话检查、导览、弹窗逻辑）

## 前台页面结构

前台是多页式站点，每个功能各自一个 HTML 文件，导览栏直接链接对应页面（不是锚点跳转）：

- `index.html` — 首页（含棋具介绍区块，未单独设页）
- `knowledge.html` — 围棋知识
- `marketplace.html` — 二手棋具交易
- `register.html` — 注册
- `login.html` — 登录
- `member-center.html` — 会员中心

没有单独的「关于我们」与「会员方案」页面——「关于正本围棋」与「联系方式」并入每一页共用的 `<footer>`，因此每页最下面都能看到。

导览栏依登录状态切换：未登录显示「注册 / 登录」，登录后显示「会员中心 / 登出」，由 `js/common.js` 依 `data-guest-only` 与 `data-member-only` 属性控制。

各页面的 header/footer 各自维护一份静态标记（没有用模板引擎做共享），若要调整导览项或页脚内容，需要在每个页面文件里同步修改。共用的 CSS 在 `css/style.css`，共用的会话检查/弹窗逻辑在 `js/common.js`，两者改一次即可对所有页面生效。

首页棋具介绍区块的图片在 `public/images/equipment/`（`goban.jpg`、`stones.jpg`、`box.jpg`、`clock.jpg`），已换成实际商品照片。

## 二手棋具交易

仅提供信息发布与留言联系功能，**不涉及任何金流/支付**，交易由买卖双方自行线下完成，平台不参与、不担保交易过程。会员发布信息需上传1-5张照片（本机存储，未接入任何云存储），填写标题、分类、使用状况、价格、联系方式，其他会员可留言联系。发布者可将自己的信息标记为已售出或下架，管理员可在后台强制下架违规信息。

分类为「棋盘 / 棋罐 / 棋子 / 计时器 / 其他」，定义在 `routes/listings.js` 的 `CATEGORIES`；前台筛选列与发布表单的下拉选项都要与它保持一致。页面为左右分栏：左侧是筛选列与信息卡片（发布日期、发布人用户名、缩图、标题、简述），右侧是平台合规声明、交易小贴士，以及「注册会员」引导（登录后自动替换为发布入口）。

### 初始内容（示范数据）

`npm run seed:demo` 会灌入 8 位已审核会员、10 条二手棋具信息与 8 条留言，作为板块上线时的初始内容，避免新站空白。**部署到正式环境后需要执行一次**，否则二手棋具交易页会是空的。脚本会在 `listings` 表非空时自动跳过，重复执行不会产生重复数据。

- 图片放在 `public/images/demo/`（共 13 张），执行时会复制到 `public/uploads/listings/`。
- 示范信息在脚本里直接写入 `active`（其中一条为 `sold`），不经过审核流程即为公开状态；一般会员发布的信息仍然是 `pending`，必须由管理员审核。
- 这些会员的登录密码统一为 `demo123456`，**上线后请立即在数据库中改掉或停用这些帐号**，否则任何人拿这组密码都能登入。
- 联系方式一律使用会员自订的微信号或做过遮蔽的手机号（如 `139****3271`），刻意不放完整手机号，避免公开展示可能指向真实第三方的号码。
- 这些内容属于平台自行准备的示范信息，不是真实会员发布的交易信息；若后续有真实会员进驻，建议逐步下架示范信息，或在页面上标注其性质。

## 注册栏位与实名方式

注册收集：用户名（3-20位字母/数字/下划线，同时是登录帐号与公开显示名称）、邮箱、密码、确认密码、身份证正面照片、身份证背面照片、棋力水平（选填）、图形验证码。**登录使用用户名 + 密码**。

实名核验的方式是「由管理员人工查看身份证照片」，平台不接入任何第三方实名认证接口，也不储存身份证号码本身。

### 身份证照片的存放（重要）

身份证照片属于敏感个人信息，处理方式如下，改动时请勿破坏：

- 存放在 `data/id-cards/`，**位于 `public/` 之外**，Express 静态服务不会提供，无法用任何公开网址取得
- 仅能透过 `GET /api/admin/members/:id/id-card/:side` 取得，该路由挂在 `requireAdmin` 之后
- 该路由以 `path.basename()` 过滤档名，防止路径穿越
- 后台列表只回传「有没有照片」的布林值，不把档名送到前端
- 注册流程中途验证失败时，会呼叫 `cleanupUploaded()` 删掉已落地的档案，避免留下无主的证件照
- `data/id-cards/` 已列入 `.gitignore`

### 图形验证码

`GET /api/captcha` 会即时产生一张 SVG 验证码，同时把答案以 JWT 签章写进 `captcha_token` cookie（有效 10 分钟）。注册时后端比对 cookie 与使用者输入，成功后立刻清除该 cookie，因此一组验证码只能用一次。服务端不需要维护 session，也不依赖任何外部服务。

## 审核机制

平台有**两道**人工审核：会员注册要审核，会员发布的二手信息也要审核。两者都在 `admin.html` 操作。

### 一、会员注册审核

会员注册后状态为 `pending`（待审核），**不会立即登录**，需管理员在「会员审核」列表中手动通过后，状态才会变成 `approved`，此时才能用用户名+密码登录。管理员也可以将会员驳回（`rejected`）或事后改判。已登录会话每次请求都会重新检查数据库中的账号状态，管理员事后驳回已通过的会员，其登录状态会立即失效。

### 二、二手信息审核

会员发布二手棋具信息后状态为 `pending`，**不会立即公开**，需管理员在「二手棋具信息」列表中通过后才会对外显示。`listings.status` 的流转如下：

| 状态 | 含义 | 谁看得到 |
| --- | --- | --- |
| `pending` | 待审核（发布后的初始状态） | 仅发布人本人（列表中标示「审核中」） |
| `active` | 审核通过，在售 | 所有人 |
| `sold` | 已售出（发布人自行标记） | 所有人 |
| `rejected` | 审核未通过 | 仅发布人本人（标示「未通过」） |
| `removed` | 已下架（发布人删除或管理员下架） | 无 |

配套的限制（都已在后端强制，不只是前端隐藏）：

- `pending` / `rejected` 的信息，其他会员与访客直接打访 `/api/listings/:id` 会得到 404
- 未公开的信息不能被留言
- 发布人不能自行把 `pending` / `rejected` 改成 `active` 或 `sold`，只能等审核
- 管理员可将已通过的信息事后驳回或下架；已 `removed` 的无法再通过

发布人看得到自己待审核的信息，是刻意的设计——否则发布后信息「凭空消失」会让人以为坏掉。相关判断依赖 `middleware/auth.js` 的 `optionalMember`（解析登录状态但不阻断请求）。

## 上线前必须完成的事

1. **换成正式的 `.env`**：`JWT_SECRET`、`ADMIN_PASSWORD` 务必换成随机长字符串，不可沿用范例值。`JWT_SECRET` 同时用于登录凭证与验证码签章，更换后所有人需重新登录。
2. **HTTPS**：请在正式环境的反向代理（Nginx / 云厂商负载均衡）上配置 SSL 证书，本项目本身不处理 HTTPS 终止。
3. **数据库**：目前用 SQLite（`data/app.db`），MVP 阶段够用；若后续并发量提升，可改接 MySQL/PostgreSQL，`db.js` 是唯一需要调整的文件。
4. **管理员帐号**：目前是单一密码登录（MVP 简化版），未来管理员多于一人时，建议改为独立帐号表。
5. **身份证照片的保存期限**：目前照片会一直保留。正式营运时建议依个人信息最小必要原则，订出审核通过后的保存期限与定期清理机制。

## 目前刻意不包含的功能

付费会员金流、棋具电商购物车/订单——目前平台仅提供免费会员注册与围棋知识浏览，尚未开放收费功能，因此未包含支付串接。待确定金流方案后再另行开发。
